# 擬回覆與新信

搭配使用：gmail-safety（寄出前確認）、thread-summary（長串先摘要）。

## 回覆流程

1. 用 `gmail_get_thread` 讀整串，不只讀最後一封
2. 找出對方要使用者回應的具體問題或請求，**逐條**列出
3. 若使用者沒說要怎麼回，而回覆內容涉及決定（同意 / 拒絕、報價、日期），先問使用者立場，不要替他決定
4. 擬草稿，呼叫 `gmail_create_draft`
5. 在對話中顯示草稿全文，問要不要修改或寄出
6. 修改用 `gmail_update_draft`，確認後用 `gmail_send_draft`

## 讓回覆接在同一串

`gmail_send_message` 沒有 thread 參數，用它回覆會變成**一封新信、不會接在原串**。所以回覆一律用草稿流程：

- 建草稿時帶入原信的 `threadId`（若 `gmail_create_draft` 支援）
- 主旨用 `Re: ` + 原主旨（原本已有 `Re:` 就不要重複加）
- 若 tool 支援標頭，設 `In-Reply-To` 和 `References` 為原信的 `Message-ID`
- 收件人：預設回原信的 `Reply-To`（沒有則 `From`）；「全部回覆」要使用者明確要求，並列出所有收件人讓他確認

如果 `gmail_create_draft` 不支援 `threadId`，告訴使用者這封會變成新的郵件串。

## 語氣對應

| 對象 | 判斷依據 | 語氣 |
|---|---|---|
| 主管 / 客戶 / 初次聯絡 | 對方用敬語、職稱、外部網域 | 正式、先結論後說明、結尾有禮 |
| 同事 | 同網域、對方語氣輕鬆 | 簡潔直接，可省略寒暄 |
| 熟人 | 對方用暱稱、表情符號 | 跟隨對方語氣 |

**語言**：跟隨對方來信的語言；對方中文用繁體或簡體也跟隨。中英混合的商務信，以對方主要語言為準。

## 寫作原則

- 第一句就回答對方最主要的問題
- 對方問了 3 件事就回 3 件事，不要漏
- 長度不超過對方來信的 1.5 倍，除非需要解釋
- 不要加「希望這封信對您有幫助」「如有任何問題請隨時聯繫」這類套話，除非使用者習慣這樣寫
- 純文字格式：不要用 Markdown 的 `**粗體**`、`#` 標題、表格；條列用 `1.` 或 `-`

## 使用者寫作風格

第一次為使用者擬信時，用 `in:sent` 讀 3–5 封他最近寄出的信，觀察：

- 開頭稱呼（「Hi XX」「XX 您好」「XX，」）
- 結尾署名（全名、英文名、職稱、有無「Best,」）
- 段落長度、是否用條列
- 慣用語

擬信時照著這些習慣寫。使用者修改草稿後，記下改了什麼，下一封照著調整。

## 新信（非回覆）

- 收件人必須是使用者提供的 email；只給名字時，用 gmail-search 從往來信件找地址，並請使用者確認
- 主旨要具體：「11/7 前請確認 Q4 預算表」優於「預算」
- 其他規則同上
