# 收件匣分類

搭配使用：gmail-search（找信）、gmail-safety（批次規則）、label-organization（標籤）。

## 流程

1. **取得標籤**：`gmail_list_labels`，記下名稱對應的 label ID（`gmail_modify_labels` 需要 ID，不是名稱）
2. **撈信**：預設 `in:inbox is:unread newer_than:7d`，`max_results` 30
3. **分類**：先用 `snippet` + 標頭判斷；只有判斷不出來時才解碼內文
4. **回報分類結果**給使用者看（見下方格式）
5. **確認後執行**貼標籤 / 封存；「需回覆」和「待辦」永遠不自動封存

## 分類標準

| 類別 | 判斷依據 | 預設動作 |
|---|---|---|
| 🔴 需回覆 | 直接寄給使用者（在 `To` 不是 `Cc`）、有問句、有人等使用者決定 | 保留在收件匣，加星號 |
| 🟡 待辦 | 有截止日、要填表 / 簽署 / 付款 / 審核，但不需回信 | 保留，加「待辦」標籤 |
| 🔵 僅供參考 | 使用者在 `Cc`、會議紀錄、公告、系統通知 | 標記已讀 |
| ⚪ 電子報 / 行銷 | `CATEGORY_PROMOTIONS`、`List-Unsubscribe` 標頭、noreply 寄件者 | 標記已讀並封存 |
| ⚫ 可封存 | 交易通知（已處理的訂單、驗證碼、登入提醒）超過 3 天 | 封存 |

**優先度提升訊號**：寄件者在使用者常往來名單（`in:sent` 裡出現過）、主旨含「急」「緊急」「urgent」「今天」「deadline」、同一串信 24 小時內多次往返。

**不確定時歸到較重要的類別**，不要把可能需要回覆的信歸成可封存。

## 標籤操作

用 `gmail_modify_labels` 加減 label ID：

- 標記已讀：移除 `UNREAD`
- 加星號：加入 `STARRED`
- 封存：用 `gmail_archive_message`（等同移除 `INBOX`）
- 自訂標籤（例如「待辦」）：先查 `gmail_list_labels` 有沒有；沒有就告訴使用者需要先建立，本工具組無法建立新標籤

## 回報格式

```
已檢查 收件匣未讀信件（近 7 天）共 23 封

🔴 需回覆（3）
- 王經理｜Q4 預算確認｜11/03 — 問你週五前能否確認數字
- ...

🟡 待辦（2）
- 人資｜年度健檢報名｜11/02 — 11/10 截止

🔵 僅供參考（6）· ⚪ 電子報（9）· ⚫ 可封存（3）

要我執行嗎？會把 🔵 標為已讀，⚪ 和 ⚫ 共 12 封封存。
```

需回覆和待辦逐封列出；其他類別只列數量，使用者要求時再展開。
