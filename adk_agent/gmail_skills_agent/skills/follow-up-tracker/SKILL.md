# 追蹤未回覆信件

## 情境 A：我寄出，對方沒回

1. 搜尋：`in:sent newer_than:30d older_than:3d -to:me`（`max_results` 30）
2. 依 `threadId` 去重，每個 thread 用 `gmail_get_thread` 讀一次
3. 判斷：thread 的**最後一封**仍是使用者寄的（`labelIds` 含 `SENT`）→ 對方未回
4. 排除不需要回覆的：
   - 使用者最後一封只是「謝謝」「收到」「好的」
   - 寄給 noreply、系統地址、郵件群組
   - 內容是單純通知、沒有問句或請求
5. 計算等待天數 = 今天 − 最後一封的 `internalDate`

## 情境 B：別人問我，我沒回

1. 搜尋：`in:inbox to:me newer_than:14d older_than:1d -category:promotions -category:social -category:updates`
2. 判斷：thread 最後一封是別人寄的、含問句或請求、使用者在 `To`（不只是 `Cc`）
3. 排除自動通知、電子報

## 輸出格式

```
⏳ 你在等回覆（3）
- 供應商 XYZ｜報價單｜已等 8 天 — 你問 12 月能否交貨
- 陳小姐｜差旅費歸屬｜已等 4 天
- 李先生｜會議時間｜已等 3 天

❗ 別人在等你（2）
- 王經理｜Q4 預算｜2 天前 — 問週五前能否確認
- 客戶 ABC｜合約第 5 條｜5 天前
```

依等待天數由久到短排序。

## 擬追蹤信

使用者要求催促時，依 reply-drafting 建草稿：

- 回覆在原 thread 內，不開新信
- 短：2–3 句，提醒原本的問題、給明確的期限或下一步
- 語氣隨等待天數調整：3–7 天客氣提醒；7 天以上可說明對使用者的影響
- 範例：「XX 您好，想跟進一下 10/27 詢問的 12 月交貨時程，我們需要在 11/10 前確認以安排生產，再麻煩您回覆，謝謝。」

**不要自動寄出追蹤信**，一律建草稿給使用者確認。
