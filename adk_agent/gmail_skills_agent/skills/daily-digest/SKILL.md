# 每日 / 每週信件摘要

適合排程執行。搭配使用：gmail-search、inbox-triage 的分類標準、follow-up-tracker。

## 時間範圍

- 每日摘要：`newer_than:1d`（週一用 `newer_than:3d` 涵蓋週末）
- 每週摘要：`newer_than:7d`
- 使用者指定的範圍優先

## 收集步驟

依序跑以下 query，每個 `max_results` 15–20：

1. **重要未讀**：`in:inbox is:unread -category:promotions -category:social -category:forums {範圍}`
2. **我被直接點名**：`to:me is:unread {範圍}`（與 1 去重）
3. **截止日相關**：`in:inbox {範圍} (截止 OR deadline OR 到期 OR "due" OR 前回覆)`
4. **等對方回覆**：見 follow-up-tracker，只列等超過 3 天的

只讀 `snippet` + 標頭來判斷；需要確認截止日或具體請求時才解碼內文。

## 輸出格式

```
📬 11/04（三）信件摘要

🔴 需要你處理（3）
1. 王經理｜Q4 預算確認 — 週五前確認數字
2. 客戶 ABC 公司｜合約修訂 — 問第 5 條能否調整
3. 人資｜年度考核 — 11/08 前完成自評

📅 近期截止
- 11/07 預算表（王經理）
- 11/08 年度自評（人資）

⏳ 你在等回覆（2）
- 供應商 XYZ｜報價單 — 已等 5 天
- 陳小姐｜差旅費歸屬 — 已等 3 天

📊 其他：12 封通知、18 封電子報（未處理）
```

## 規則

- 「需要你處理」最多列 10 項，依急迫度排序；超過時寫「另有 N 封，要展開嗎？」
- 每項一行，寫清楚**對方要什麼**，不要只抄主旨
- 沒有需處理的信時，直接說「今天沒有需要你處理的信」，不要硬湊內容
- 摘要是唯讀的：**不要**自動標記已讀、封存或貼標籤，除非使用者在設定排程時明確要求
- 排程執行時沒有人可以回答問題，遇到授權過期就在摘要中寫明「Gmail 授權已過期，請重新授權」並附上 `auth_url`
